THE ACCURACY CHECKER (rebuilt in the baseline stage, Nov 19 2026)

What it checks
  Eight rules every quote must keep, written from the audit and the owner decisions (OD1-OD11):
  - items_add_up            the items printed under an option add up to its printed total (S1-F2)
  - same_work_same_price    the same work item in the same area has one price in every option (S1-F3, OD2)
  - options_step_up         the options shown do different work and each costs more than the one before (S1-F7, OD6)
  - labels_match_work       titles and bullets promise only priced work: "to Code", "Remove", "Air seal" (S1-F7)
  - cavity_not_overfilled   what is installed fits the cavity with what is already there; a wall with no
                            depth is a 2x4, 3.5 in (S1-F4, S1-F5, S1-F6, OD5)
  - finite_amounts          no blank, infinite or negative amount (a price adjustment line may be negative)
  - same_price_text         every surface reads an option's price in whole dollars, and every list shows the
                            recommended option's price (S1-F1, OD1, OD4); surfaces in PRICE_SURFACES
  - valid_until_is_expiry   "Valid until" is the business-zone day the link stops working (S1-F8, OD11)
  Engine rules: lib/pricing/invariants.ts. Quote rules: lib/quotes/invariants.ts. Unit tests on hand-made
  good and bad quotes: lib/accuracy/invariants.test.ts.

How to run it
  npm run accuracy:violations -- 10000 20261118
      10,000 random quotes (lib/pricing/__fixtures__/random.ts) from seed 20261118, priced with the
      seeded setup; prints per rule the quotes that break it, the breaks and the breaks by kind.
      Takes about 70 s. Add --rows <rows.json> to price with other pricing rows.
  node scripts/accuracy/run.mjs scripts/accuracy/price-golden.ts synthetic <out.json>
      The 65 synthetic estimates (scripts/accuracy/golden-synthetic.json, written by make-synthetic.ts).
  node scripts/accuracy/run.mjs scripts/accuracy/price-golden.ts live <golden dir> <out.json> [<summary.json>]
      The live estimates. The export is read-only and never committed:
        1. run scripts/accuracy/golden-export.sql and scripts/accuracy/bundle-rows.sql (as
           select rows::text as rows_text, md5(rows::text) as md5 from (...) x) on production, SELECT only;
        2. node scripts/accuracy/run.mjs scripts/accuracy/make-live-golden.ts <estimates result> <rows result> <golden dir>
           checks the copy against the database's md5 and counts and writes live-estimates.json and live-rows.json.

Keeping it true
  - shownOptions (lib/pricing/invariants.ts) is what the customer is shown. The engine returns only shown
    options (with OD6, unless asked for all); an option marked hidden is never counted.
  - Job-level customer lines (travel, minimum, adjustment) have no area and are not "work".
  - PRICE_SURFACES lists each place a price is printed with its file, line and snippet; a test fails when
    a snippet leaves its file. When a surface changes, update its entry and priceTexts with it.
  - After a migration that changes a seeded value: DATABASE_URL=... bash scripts/accuracy/seeded-rows.sh
    and commit lib/pricing/__fixtures__/seeded-rows.json with the migration. A new pricing setting key
    goes in PRICING_SETTING_KEYS (lib/accuracy/rows.ts) and in bundle-rows.sql.

Before any fix (docs/accuracy/before/)
  violations-20261118.txt, golden-synthetic-before.json (in full), golden-live-before.json (counts and
  option totals by estimate id only).
