HEADLINE CHANGES FROM OD15 (review B flow-B4; branch claude/accuracy-fixb-screens)

The rule (lib/field/recommended.ts, used by the phone's dock, cards, list and Send step, the office
list, the sync's model_total_price and the customer quote):
  recommended = the option the estimator picked; with no pick, Better, the implied pick (OD15).
  When that option is not shown (OD6): the option shown that does the same work (the engine marks
  it: PricedOption.sameWorkAs), else the nearest option shown above it, else the nearest below.
Before: a hidden pick went to the next option shown after it, else the nearest before; with no
pick, Better if shown, else the FIRST option shown (Good, the cheapest, whenever Good was shown).

Random-quote counts: node scripts/accuracy/run.mjs scripts/accuracy/od15-headlines.ts <count> <seed>

WHAT THE OFFICE LIST CANNOT SEE
  The office list reads the stored options, which keep tier and price only (estimate_options), so it
  takes the "nearest above, else below" steps without the "same work" step. It names a different
  option from the phone and the quote only for an estimate whose Better is hidden as the same work
  as Good while Best is shown: none in either golden set, none in production's stored rows, none in
  50,000 random quotes. The checker would report such an estimate (same_price_text office_list).
  Closing it for good needs the recommended tier stored with the estimate (an additive column the
  sync writes); that is a migration, outside this branch.

SENT AND SIGNED QUOTES (hard rule 1)
  Unchanged. A sent quote keeps its stored document's recommendedTier; app/api/quotes/route.ts
  stores selected_tier = the document's recommendedTier at send, so the office shows the option the
  customer was sent. Only drafts priced from now on, with no pick and Better hidden, move.
