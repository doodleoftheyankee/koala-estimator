Why the release cannot change a stored quote
  - Nothing in the release touches the quote code: the blower door files, the menu, the service
    worker, /unreachable's offer of the phone's copy, lib/format.ts (one new function, fixed(),
    which no quote uses) and the blower door migration are all outside lib/quotes and app/q.
  - The blower door migration adds one app_settings row ('blower_door', only when absent), a read
    policy on app_settings for that row, a new table with its triggers, policies and grants, and
    new functions. It touches no quote, snapshot, PDF path, e-sign record or other setting.
  - The accuracy migration is unchanged from claude/accuracy: its conditional seed replacements
    apply only to rows that still equal the seed, and a stored quote reads its company, terms,
    warranty, consent, number and dates from its own document (docs/accuracy/final/hard-rule-1.txt).

To repeat it
  1. Render the release head: node scripts/accuracy/render-run.mjs scripts/accuracy/render-stored.ts
     <export> <release>.
  2. git archive 30afd15 into a folder, link node_modules, run the same command there into
     <accuracy>; diff -rq <accuracy> <release> (expect nothing).
  3. Render 7c6b08c the same way (with render-run.mjs, render-stored.ts and stubs/ copied in) into
     <before>; python3 -I scripts/accuracy/hard-rule-1-diff.py <before> <release>.
  4. git archive origin/main, copy render-run.mjs, stubs/ and render-docs-only.ts into its
     scripts/accuracy/, run render-docs-only.ts there into <main>, and cmp each of its 1,386 files
     with the same file in <release>.
